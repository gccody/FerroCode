# Ferro Code audit — 12 September 2026

The highest priorities are permission correctness, protection of local history, and reliable turn lifecycle handling. Application source was not changed during this review.

Implementation follow-up: the findings below describe the pre-fix baseline. Fixes and requested roadmap items 1, 2, 4, and 5 are tracked in [reliability-release.md](reliability-release.md); the regression checks now live in the workspace test suite.

## Scope and evidence

Reviewed the domain and persistence layer, application state and controller, embedded SDK and CLI transport, Git/workspace operations, updater, desktop callbacks and view projection, Markdown rendering, Slint components, build configuration, CI, and the differences between the vendored PTY crate and its pinned upstream source. This is a source audit with local execution checks, not a claim that every possible defect has been found. macOS/Linux desktop behavior and live authenticated model sessions were not exercised.

The findings below distinguish executable reproductions from source traces. Isolated regression checks live under `target/audit-state`; they use the actual state source and a copy of the controller with a transport stub, so they validate controller logic without contacting a model. They are temporary audit artifacts, not additions to the normal test suite. Eight assertions of desired behavior fail on the current code. A separate executable parsed the actual `turn/start` JSON through the pinned SDK types and confirmed the sandbox override disappears.

## Findings, ordered by priority

### 1. High — changing an existing thread to read-only does not update its sandbox

Location: `crates/ferro-code-app/src/controller.rs:972`.

`thread/start` accepts a `sandbox` mode, but `turn/start` expects `sandboxPolicy`, a structured policy. The controller reuses `sandbox` for turns. The pinned `TurnStartParams` silently ignores this unknown field. Reproduction: start a writable thread, select read-only, and send another message. The UI shows read-only while the backend retains the thread's previous policy. The reverse change also fails to grant the requested permissions.

Verified by parsing the request through the pinned `ClientRequest`: both the reserialized `sandbox` and `sandboxPolicy` are null. Build requests with typed protocol structs and explicitly convert the selected mode to a policy. Test permission transitions on a reused runtime thread.

### 2. High — background file approvals can identify the wrong project

Location: `crates/ferro-code-app/src/controller.rs:1565`.

When a file-change approval does not supply `grantRoot`, its displayed target falls back to the currently selected workspace, ignoring the request's `threadId`. Start work in project A, switch to project B, and receive A's approval: the dialog identifies B as the target. The user can approve edits based on an incorrect directory label. Approval records also omit the originating local thread, preventing reliable ownership display and cancellation cleanup.

An eighth isolated regression reproduced the incorrect project label. Resolve approval ownership through the runtime-thread mapping and display the originating project/thread and affected paths. Never substitute the foreground workspace for an unknown request origin.

### 3. High — a load error can lead to overwriting the user's history with defaults

Locations: `crates/ferro-code-desktop/src/main.rs:80`, `:164`, `:171`.

Every load error, including malformed JSON, becomes an empty default state. Autosave and shutdown then write that state over the original file if writing succeeds. A truncated or incompatible state file therefore loses its recoverable contents without a recovery prompt or diagnostic. Save failures are also silently discarded.

Keep a failed load distinct from a missing file, preserve the original bytes, provide a recovery path, and suspend replacement of the failed store until recovery is resolved. Surface persistent write errors to the user.

### 4. High — staged persistence deletes the only committed state before replacement

Location: `crates/ferro-code-core/src/persistence.rs:74`.

Saving writes `state.json.tmp`, removes `state.json`, then renames the temporary file. A crash or failed rename between deletion and replacement leaves no primary state file. Loading ignores the temporary file. Two app instances also share this temporary filename and can overwrite each other's snapshots.

Use a platform-correct atomic replacement, durable writes, a recoverable previous generation, and single-writer coordination. Test failures between each persistence operation. This is a separate problem from the startup error handling in finding 3.

### 5. High — adding a new project discards unsynchronized conversation updates

Location: `crates/ferro-code-app/src/state.rs:300`.

The new-project branch clears `conversation` without first calling `sync_active_conversation`. Streamed assistant text is held in that active vector until a save, thread switch, or completion synchronizes it. Add another project before that synchronization and return to the first thread: the recent response text has disappeared. Subsequent background deltas can rebuild only its remaining suffix.

A regression using the production state source reproduced a message count of zero instead of one. Synchronize the active conversation before changing project ownership, as `select_project` already does.

### 6. High — turn response/notification ordering can leave a finished thread busy

Locations: `crates/ferro-code-app/src/controller.rs:914`, `:1223`; `crates/ferro-code-protocol/src/lib.rs:286`.

The SDK response is forwarded from a spawned task independently of notifications. A `turn/completed` notification can clear the running turn before the corresponding `turn/start` response is processed. The response unconditionally inserts it back into `running_turns`. The composer then stays disabled for a turn which already finished.

The reversed-order regression reproduced this. The related interrupt response also clears state by local thread alone, so a late acknowledgement can affect a newer turn. Track lifecycle by both thread and turn/request generation; make completion terminal and ignore stale acknowledgements.

### 7. High — CI selects a compiler older than the declared minimum

Locations: `.github/workflows/ci.yml:25`, `Cargo.toml:15`.

All three CI jobs install Rust 1.92.0, while all workspace packages declare Rust 1.95. Cargo rejects that combination before tests execute. Align the workflow with the supported compiler, preferably from one checked-in toolchain definition. The current CI configuration cannot provide the intended regression protection.

### 8. Medium — CLI EOF is not reported as a disconnect

Location: `crates/ferro-code-protocol/src/lib.rs:115`.

The stdout reader emits `backend/exited` on an I/O error, but ordinary EOF simply ends the loop. A terminated child normally produces EOF. The controller can remain connected with pending calls and a permanently busy turn until a later write happens to fail. `try_recv().ok()` also hides channel disconnection.

Report normal EOF, monitor/reap the child, distinguish an empty queue from a disconnected queue, and fail pending operations on transport closure.

### 9. Medium — valid string request IDs are ignored

Location: `crates/ferro-code-app/src/controller.rs:762`.

Server requests are dispatched only inside the `id.as_u64()` branch. A request with a string ID falls through to notification handling and is ignored. Both JSON-RPC and the pinned `RequestId` support strings. A backend using string IDs can wait indefinitely for approval or user input that the desktop never displays.

The string-ID approval regression reproduced an empty approval queue. Dispatch server requests by the presence of `method` and `id`; preserve the full request ID. Numeric matching can remain specific to locally generated client request IDs.

### 10. Medium — question choice clicks do not reliably update the displayed selection

Locations: `crates/ferro-code-desktop/src/callbacks.rs:898`, `crates/ferro-code-app/src/controller.rs:131`, `crates/ferro-code-desktop/ui/overlays.slint:271`.

The answer callback changes state but does not synchronize the UI. `poll()` compares the revision at entry with the revision at exit, so it does not detect edits made before polling. While the backend is waiting for input, there may be no further event to trigger synchronization. The selected button and answer field continue to show the previous value, although submitting sends the new value.

The revision regression reproduced `poll() == false` after a question edit. Track the last rendered revision across ticks or update the relevant model in the callback. Apply the same rule to reset/usage callbacks that currently rely on unrelated events to refresh progress state.

### 11. Medium — pasted image history breaks after the application exits

Locations: `crates/ferro-code-desktop/src/main.rs:98`, `crates/ferro-code-desktop/src/callbacks.rs:636`, `crates/ferro-code-app/src/controller.rs:1672`.

Pasted images are written under an owned `TempDir`, while their paths are serialized into permanent history. Normal shutdown deletes those files. Reopening the conversation cannot load its image thumbnails. Separately, reconstruction of a runtime thread only includes message bodies, omitting historical attachments even when an attached file still exists. Follow-up questions about previously supplied images lose their visual context after restart.

Copy sent attachments into managed durable storage and include attachment references/content in conversation restoration. Define retention and missing-file behavior explicitly.

### 12. Medium — thread IDs can collide after a deletion

Location: `crates/ferro-code-app/src/state.rs:336`.

IDs use the current second and `threads.len() + 1`. Create two threads within one second, remove the first, and create another in that same second: the new ID equals the second thread's ID. Selection, message synchronization, runtime mappings, and removal then address the wrong or multiple threads.

The regression produced `thread-2-2` for both surviving and new threads. Use collision-resistant IDs or a persistent monotonic allocator independent of collection length.

### 13. Medium — a project inside a larger repository can commit changes outside that project

Location: `crates/ferro-code-app/src/workspace.rs:141`.

Any directory can be added as a project. `git -C <subdirectory> add --all` without a pathspec stages changes across the repository, and the subsequent commit commits the complete index. Selecting a subproject can therefore commit sibling-project changes and pre-existing staged changes. The UI exposes no scope review before this operation. A disposable repository reproduction confirmed that staging from `project-a` also staged `project-b/b.txt`.

Resolve the repository root and make repository-wide scope explicit, or implement project-scoped staging and commit semantics that also account for an already-populated index. A file-selection/commit-review screen should show the exact content to be committed.

### 14. Medium — AI commit summaries omit staged changes and new file contents

Location: `crates/ferro-code-app/src/workspace.rs:118`.

The summary reads plain `git diff`, which contains unstaged tracked edits. Fully staged edits have no patch here; untracked files contribute only status filenames. The eventual `git add --all` commits both. The generated subject is therefore based on different content from the commit. Edits made while the summary runs widen the mismatch.

Generate the summary from the exact reviewed/staged snapshot and check that it has not changed before committing. Include suitable bounded content for new files.

### 15. Medium — case-sensitive project paths are incorrectly merged

Location: `crates/ferro-code-app/src/state.rs:304`.

Project deduplication uses `eq_ignore_ascii_case` on every platform. On a case-sensitive filesystem, `/work/App` and `/work/app` may be different projects, but adding the second selects the first. This can route the next prompt into the wrong directory. The workspace result comparison also uses case-insensitive equality unconditionally at `controller.rs:163`.

Use one consistent platform/filesystem-aware identity policy. The controller already has a platform-conditional `same_workspace` helper, but these paths bypass it.

### 16. Medium — failed command/tool outcomes are flattened into completed items

Locations: `crates/ferro-code-app/src/controller.rs:1424`, `:1582`.

Ingestion derives status solely from whether the notification is `item/completed`. It discards the item's failed/declined status and command exit code. A failed command with no output becomes indistinguishable in the stored activity record from a successful completed command. Tool result/error fields are also omitted in favor of arguments.

The failed-command regression returned `completed` instead of `failed`. Preserve protocol outcome and exit code separately from lifecycle completion, retain tool errors/results, and display an error state in the activity card.

### 17. Medium — Stop does nothing while thread/turn startup is pending

Location: `crates/ferro-code-app/src/controller.rs:460`.

Sending immediately marks the thread busy and shows Stop. Until both runtime thread and turn IDs exist, `interrupt()` silently returns without recording cancellation. If the user presses Stop during slow startup, the queued operation still begins later.

Record a cancellation intent tied to the pending request. Prevent a turn from starting if cancellation occurs before thread creation; otherwise interrupt as soon as the turn ID becomes available.

### 18. Medium — Git filename parsing does not handle quoted paths

Locations: `crates/ferro-code-app/src/workspace.rs:295`, `crates/ferro-code-desktop/src/workspace_view.rs:11`.

Git's ordinary text output quotes/escapes some filenames, including non-ASCII names under the default quoting configuration. `ls-files` output is treated as literal paths, and status parsing trims/splits paths without decoding Git quoting. The tree can show escape sequences instead of actual names and fail to correlate changed files correctly; newline-containing names are also split into records.

Use NUL-delimited machine-readable Git output, parse status and rename records explicitly, and keep paths separate from display strings.

### 19. Low — rate-limit errors leave loading state set

Location: `crates/ferro-code-app/src/controller.rs:769`.

The successful rate-limit response clears `usage_loading`, but the error branch does not. It also never populates the dedicated `usage_error` field. The regression reproduced the flag remaining true. The current projection does not expose these fields, limiting the immediate visible effect, but the state contract is broken and cannot support accurate loading/error feedback.

Clear operation flags and set the operation-specific error on every terminal path, including send failures and disconnects.

## What to implement next

1. **A reliability release.** Fix findings 1–10 and the CI compiler first. Add deterministic tests for event reordering, pending cancellation, transport EOF, malformed storage, failed replacement, and multiple open instances. Keep the transport injectable so these checks require no model calls.
2. **Durable conversation storage.** Replace whole-history autosaves on the UI thread with a serialized background persistence service, per-thread records or transactions, schema versions, recovery generations, and durable attachments. Give users export, backup/recovery, and an undoable archive action. The current archive action permanently removes the local record.
3. **A reviewable Git workflow.** Show actual diffs, selected files, staged/unstaged state, commit subject editing, and explicit repository scope. Generate summaries from the selected snapshot. Handle non-GitHub origins and behind/diverged branches rather than presenting all non-ahead states as up to date.
4. **Connection recovery and diagnostics.** Add reconnect/retry, startup and request deadlines, visible backend identity/version, and a diagnostic export. Clear old runtime mappings and approval/question queues when a backend generation ends. CLI updates currently apply only to fallback operation; embedded SDK updates require an application release.
5. **Conversation continuity and UI polish.** Keep draft text and attachments per thread/project; restore the relevant attachments and context after restart; make tool errors and approval ownership visible. Move blocking Git diff collection and large attachment decoding off the UI thread. Cache Markdown and image previews with bounded retention, and measure wrapped message height from the actual available width.

The four-crate separation is useful and should be retained. The biggest architectural gap is that protocol payloads, asynchronous lifecycle state, and the desktop's render revision are still coupled through ad hoc JSON and callbacks. Typed requests, explicit operation states, and a consistent state-to-view update boundary would prevent several findings together.

## Additional maintenance observations

- README describes the software renderer, but `Cargo.toml` enables Skia. It also links to `docs/refactor-notes.md`, which is absent from the checkout.
- The updater's report parsing has narrow fixture coverage; validate it against the supported CLI versions without installing updates during tests.
- The vendored PTY code differs minimally from the pinned implementation, but its omitted upstream integration test is not replaced by the workspace test command. Preserve a documented regression check for the Windows patch.
- No new exploitable issue was established in the native window-handle code or PTY patch. That is not equivalent to platform runtime validation.
